# 메모 폴더 · 제목과 구분선 · 보기 설정 설계

- 날짜: 2026-11-21
- 대상: `src/features/memo/`, `memo_blocks` 테이블, `/api/memo/*`
- 상위 설계: `docs/superpowers/specs/2026-11-14-daily-routine-app-design.md` §5.3(메모장), §9.1(메모 파일)
- 표시: **[결정]** 사용자가 정한 것 · **[제안]** 대화에서 사용자에게 보여 주고 동의를 받은 것 · **[제안, 새로]** 이 문서를 쓰면서 정한 것(사용자가 아직 못 봄) · **[빌더 재량]** 만드는 사람이 정한다

## 1. 요청

사용자 요청(원문):

- 메모 앱에 폴더 기능 추가. 폴더 하위에 메모를 넣을 수 있어야 함
- 메모 리스트 숨김 처리 기능 → "메모 리스트를 여닫을 수 있어야 해" **[결정]**
- `---`를 넣으면 구분선이 생기는 기능
- h1, h2, h3 기능 추가
- 글씨 크기 조절 기능 → "메모 화면 전체" **[결정]**
- 메모장 하단에 기본적으로 여백이 있어서 스크롤이 가능하도록 개선
- 아이콘 색 조절 기능. 기본적으로 같은 폴더 안의 메모는 같은 색

이유는 따로 듣지 않았다. 상위 설계 §5.3의 "굵게 밖의 서식은 없다"와 §9.1의 "폴더는 이번에 넣지 않는다"를 이 문서가 바꾼다.

## 2. 목표 · 비목표 · 안티목표

**목표**
- 폴더 한 단계로 메모를 묶는다. 맥과 아이폰에서 같은 폴더가 보인다.
- 폴더 색이 안에 든 메모 색의 기본이 되고, 메모마다 따로 고를 수 있다.
- 편집기에서 `#`·`##`·`###` 제목과 `---` 구분선을 쓴다.
- 메모 화면의 글씨 크기를 기기마다 고른다.
- 넓은 화면에서 메모 목록을 접고 편다.
- 메모 끝에 빈 공간을 두어 마지막 줄을 화면 가운데까지 올려 쓸 수 있다.

**비목표**
- 폴더 안의 폴더. **[결정: 한 단계]**
- 끌어다 놓아 옮기기. 이번에는 칩과 창으로만 옮긴다. **[제안]**
- 글의 일부만 크게 하는 서식, 그 밖의 마크다운(기울임, 링크, 코드, 표 등).
- 폴더 순서를 직접 바꾸기. 가나다순으로 고정한다. **[제안]**
- 글씨 크기와 목록 여닫기를 기기 사이에 맞추기. 둘 다 기기마다 따로다. **[제안]**
- 인터넷 없이 폴더를 만들거나 메모를 옮기기. **[결정]** (글 입력의 기기 보관은 지금처럼 된다. 폴더 안에서 새 메모를 쓰는 것도 끊긴 상태에서 된다.)

**안티목표** (돌아가더라도 이러면 실패)
- 메모 글이 사라지거나 덮어써진다. 폴더를 지웠더니 메모가 지워지거나, 폴더를 옮겼더니 다른 기기에서 쓴 글이 덮어써지거나 충돌 사본이 생기면 실패다. 상위 설계 §5.3 "메모 유실 금지"를 그대로 지킨다.
- `#`이나 `---` 같은 기호가 목록의 이름과 미리보기에 그대로 보인다.
- 아이폰에서 입력할 때 화면이 저절로 확대된다.
- 이번 작업 때문에 기존 메모의 색이 예고 없이 바뀐다. 폴더 밖에 있고 색을 고른 적 없는 메모는 지금 색을 그대로 유지한다. 폴더를 지웠을 때도 안에 있던 메모의 색은 바뀌지 않는다(§5.2).

## 3. 제약

- **Next.js 16.4:** `AGENTS.md`에 따라 라우트 코드를 쓰기 전에 `node_modules/next/dist/docs/`를 읽는다.
- **DB:** Drizzle 마이그레이션(`drizzle/`)을 쓴다. 운영은 Postgres(Supabase), 로컬은 PGlite다. 새 테이블은 `0002_enable_rls.sql`처럼 RLS를 켠다.
- **저장 형식:** 본문은 지금처럼 평문 그대로 저장한다(`**굵게**`, `# 제목`, `---`). 표시만 편집기가 바꾼다.
- **아이폰 확대:** iOS는 16px보다 작은 글씨의 입력칸에 초점이 가면 화면을 확대한다. 그래서 휴대폰 편집기 글씨는 지금 16.5px이다.
- **단축키:** 이미 쓰는 키는 ⌘\(앱 메뉴 여닫기, 상위 설계 §9.2, `AppShell.tsx`), ⌘B(굵게), ⌘N(새 메모), ⌘F(메모 찾기), ⌘Enter(새 메모)다.
- **색:** 색연필 일곱 색(`src/ui/hues.ts`의 `HUES`)과 `--hue` 변수(상위 설계 §9.4, §10)를 쓴다. 색은 면에만 칠하고, 그 위 글자는 `--on-index`로 쓴다.
- **기기별 설정:** `src/features/shell/prefs.ts`의 `readPref`·`writePref`(`daily:` 접두어)를 쓴다.
- **새로 설치할 패키지는 없다.**

## 4. 접근 방식

**폴더와 색의 저장**
1. **DB에 폴더 테이블을 만들고, 메모에 폴더 칸과 색 칸을 둔다. 폴더와 색을 바꾸는 요청은 본문 저장과 따로 보낸다. — 이것으로 한다. [제안]** 맥과 아이폰에서 같은 폴더가 보인다. 폴더·색 변경은 본문 `version`을 올리지 않으므로, 한 기기에서 옮기는 동안 다른 기기에서 쓴 글과 부딪히지 않는다.
2. 본문 맨 위에 폴더와 색을 글로 적기. DB를 고칠 필요는 없지만, "첫 줄이 메모 이름"(§9.1) 규칙이 깨진다. 폴더 이름을 바꿀 때마다 안의 메모 본문을 전부 고쳐야 하고, 그때마다 충돌이 생길 수 있다. 버린다.
3. 기기에만 저장하기. 맥에서 만든 폴더가 아이폰에 보이지 않는다. 버린다.

**제목과 구분선의 표시**
1. **굵게(`editor/bold.ts`)와 들여쓰기 안내선(`editor/guides.ts`)처럼 CodeMirror 꾸밈으로 직접 그린다. — 이것으로 한다. [제안]**
2. `@codemirror/lang-markdown`을 들인다. 쓰는 문법이 세 가지뿐이고 이미 만든 굵게 처리와 겹친다. 패키지 무게에 비해 얻는 게 없다. 버린다.

## 5. 설계

### 5.1 데이터 **[제안 / 세부는 빌더 재량]**

- 새 테이블 `memo_folders`
  - `id` uuid 기본키
  - `name` text, 필수. 앞뒤 공백을 지우고 1~40자로 한다. 이름이 같은 폴더도 허용한다. **[제안, 새로]**
  - `hue` text, 필수. `HUES` 중 하나다.
  - `created_at`, `updated_at`
- `memo_blocks`에 칸 두 개를 더한다.
  - `folder_id` uuid. 비어 있을 수 있고 `memo_folders(id)`를 가리킨다. **ON DELETE SET NULL**이라 폴더를 지워도 메모는 남는다.
  - `hue` text. 비어 있을 수 있다. 비어 있으면 "자동"이다. 폴더 안이면 폴더 색을, 폴더 밖이면 지금처럼 메모마다 정해진 색(`hueFor`)을 쓴다.
- 마이그레이션 `0003`에서 테이블을 만들고, 칸을 더하고, `memo_folders`에 RLS를 켠다. 기존 메모는 두 칸이 모두 비어 있으므로 모양이 그대로다.
- `src/shared/contracts.ts`
  - `MemoBlock`에 `folderId: string | null`, `hue: Hue | null`을 더한다.
  - `MemoFolder { id, name, hue, createdAt, updatedAt }`를 새로 둔다.

### 5.2 API **[제안 / 세부는 빌더 재량]**

모두 `withUser`, `readBody`, zod로 받고, 오류 문구는 지금처럼 한국어로 쓴다.

| 요청 | 내용 |
|---|---|
| `GET /api/memo/blocks` | `{ blocks, folders }`. 한 번 불러올 때 폴더도 함께 받는다. 따로 `GET /api/memo/folders`로 나눠도 된다. **[빌더 재량]** |
| `POST /api/memo/blocks` | 지금 받는 값에 `folderId?`, `hue?`를 더한다. **없는 `folderId`는 오류로 막지 않고 폴더 밖으로 만든다.** 기기에 보관해 둔 글이 서버에 처음 갈 때 그 사이 폴더가 지워졌더라도 글을 잃지 않기 위해서다. **[제안, 새로]** |
| `PATCH /api/memo/blocks/[id]` | `{ folderId?: string \| null, hue?: Hue \| null }` → `MemoBlock`. **`version`과 `updated_at`은 바꾸지 않는다.** 그래서 메모를 옮겨도 목록 순서가 바뀌지 않고, 본문 저장과도 부딪히지 않는다. 두 기기에서 동시에 바꾸면 나중에 도착한 쪽이 이긴다. 없는 `folderId`는 400, 없는 메모는 404다. |
| `POST /api/memo/folders` | `{ name, hue? }` → 201 `MemoFolder`. `hue`가 없으면 아직 아무 폴더도 쓰지 않은 색을 `HUES` 순서대로 고르고, 다 쓰였으면 가장 적게 쓰인 색을 고른다. |
| `PATCH /api/memo/folders/[id]` | `{ name?, hue? }` → `MemoFolder` |
| `DELETE /api/memo/folders/[id]` | 204. 안에 든 메모는 폴더 밖으로 나온다. 색을 따로 고르지 않은 메모(`hue`가 비어 있음)에는 같은 트랜잭션 안에서 폴더 색을 먼저 옮겨 적는다. 그래서 폴더를 지워도 메모 색이 그대로다. 메모마다 고른 색도 그대로 둔다. 이때도 `version`과 `updated_at`은 바꾸지 않는다. **[제안, 새로]** |

### 5.3 클라이언트 상태 (`store.ts`, `client.ts`, `draft.ts`)

- `PadState`에 `folders`를, `PadBlock`에 `folderId`와 `hue`를 더한다.
- **불러와 합치기:** 폴더 목록과 메모의 `folderId`·`hue`는 늘 서버 값을 따른다. 본문이 저장을 기다리는 중이어도 마찬가지다. 본문만 지금처럼 "저장 안 한 글이 화면에서 이긴다"를 따른다.
- **아직 서버에 없는 메모**(`id`가 없음)
  - 폴더 줄의 ＋로 만들었다면 `folderId`를 들고 있다가 `createBlock`에 함께 보낸다.
  - 이 상태에서 옮기거나 색을 바꾸면 기기 안의 값만 바꾸고, 만들 때 함께 보낸다.
- **기기 보관(`draft.ts`):** 서버에 한 번도 가지 못한 메모의 보관본에는 `folderId`와 `hue`도 함께 남긴다. 예전 형식의 보관본(v1)은 두 값을 비어 있는 것으로 읽는다.
- **충돌 사본**은 원래 메모의 `folderId`와 `hue`를 물려받는다. 다른 기기에서 지운 메모의 저장 안 된 글을 새 메모로 살릴 때도 마찬가지다(폴더가 아직 있을 때).
- **폴더 작업과 옮기기·색 바꾸기**는 화면에 먼저 반영하고 서버에 보낸다. 실패하면 화면을 되돌리고 안내한다. 예: "인터넷에 연결되지 않아 옮기지 못했어요. 연결되면 다시 해 주세요." 다시 보내는 줄(retry queue)은 두지 않는다. **[결정: 바로 되돌리고 알리기]**
- 다른 기기에서 바꾼 폴더는 지금처럼 화면으로 돌아올 때(`visibilitychange`) 다시 불러와 반영한다.

### 5.4 목록 화면 **[제안]**

```
🔍 메모 찾기               📁＋  ＋
▾ ● 회사                    …  ＋
     ▪ 주간 회의        오후 3:12
     ▪ 1:1 메모              어제
▸ ● 개인                    …  ＋
──────────────────────────────
  ▪ 장보기               11월 3일
  ▪ 아이디어             11월 1일
```

- **순서:** 폴더를 가나다순(`localeCompare(…, "ko")`)으로 위에 놓고, 그 아래에 폴더 밖 메모를 둔다. 폴더 안과 밖 모두 최근에 고친 메모가 위에 온다.
- **폴더 줄:** 여닫는 표시(▸/▾), 색 점, 이름, … 버튼, ＋ 버튼이 있다. 줄을 누르면 열고 닫는다.
  - 처음에는 모두 펼쳐 둔다. 닫은 폴더의 id만 기기에 기억한다(`memo.closedFolders`). 그래서 새로 만든 폴더는 펼쳐진 채로 나온다. **[제안, 새로]**
  - 빈 폴더를 열면 "메모가 없어요" 한 줄만 보인다.
- **📁＋**(목록 머리, ＋ 옆): 폴더 이름을 받아 만든다. 휴대폰은 Sheet로 받는다. 넓은 화면에서 Sheet로 받을지 목록 안에서 바로 받을지는 **[빌더 재량]**이다.
- **… 메뉴:** 이름 바꾸기, 색 바꾸기, 폴더 지우기가 있다.
  - 지우기 전에 확인을 받는다. "‘회사’ 폴더를 지울까요? 안에 든 메모 3개는 지우지 않고 폴더 밖으로 꺼내요."
- **새 메모:** 폴더 줄의 ＋는 그 폴더 안에 만든다. 맨 위 ＋, ⌘N, ⌘Enter, 다른 화면의 빠른 추가, 일정에서 만든 메모는 폴더 밖에 만든다.
- **검색:** 지금처럼 메모 내용과 일정 제목을 찾는다. 폴더 이름은 찾지 않는다. **[제안, 새로]**
  - 검색어가 있으면 맞는 메모가 든 폴더만 닫힘 상태와 상관없이 펼쳐 보이고, 그 안에서도 맞는 메모만 보인다.
  - Enter는 화면에 보이는 순서대로 첫 메모를 연다.
- **메모 색**(목록의 아이콘·칸, 열린 메모의 줄 바탕, 편집 중인 줄. 지금 `--hue`가 칠하는 모든 곳)
  - 폴더 안: 메모 `hue` ?? 폴더 `hue`
  - 폴더 밖: 메모 `hue` ?? `hueFor(id ?? key)`
  - 칩으로 메모를 직접 폴더 밖이나 다른 폴더로 옮기면, 색을 따로 고르지 않은 메모는 새 자리의 규칙을 따른다. 폴더 색이 메모에 남지 않는다. 폴더를 지울 때만 색을 옮겨 적는다(§5.2). **[제안, 새로]**
  - 참고: 지금은 `hueFor(key)`라서 새 메모는 새로고침 전까지 기기 키로 색이 정해지고, 새로고침 뒤에는 서버 id로 다시 정해진다. `id ?? key`로 바꾸면 id를 받는 순간 한 번만 바뀐다. 바꿀지는 **[빌더 재량]**이다.
- **닫힌 폴더 안의 메모가 열려 있을 때**(넓은 화면) 폴더 줄에 그 사실을 표시하는 방법은 **[빌더 재량]**이다.

### 5.5 메모 머리 막대 **[제안]**

```
넓은 화면  [◧] [● 회사 ▾]                 저장했어요  [가] [🗑]
휴대폰     [< 메모] [● 회사 ▾]            저장했어요  [가] [🗑]
```

- **폴더 칩:** 지금 폴더의 이름과 메모 색 점을 보여 준다. 폴더 밖이면 "폴더 없음"이라고 쓴다. 일정 메모에도 칩이 있다.
- 칩을 누르면 "폴더와 색" Sheet가 열리고, 고르는 즉시 적용된다.
  - 폴더 고르기: "폴더 없음"과 모든 폴더 중 하나를 고른다. 지금 폴더에 체크 표시가 있다.
  - 색 고르기: 일곱 색 중 하나, 또는 "폴더 색 따르기"(폴더 안일 때)나 "자동"(폴더 밖일 때)을 고른다.
- 휴대폰 폭이 좁으면 칩 이름을 말줄임으로 줄인다. "저장했어요"를 줄이거나 숨길지는 **[빌더 재량]**이다.

### 5.6 목록 여닫기 (900px 이상만) **[결정: 여닫기 / 제안: 세부]**

- 머리 막대 맨 왼쪽의 ◧ 버튼과 **⌥⌘S**로 접고 편다. Apple 메모 앱에서 폴더 목록을 여닫는 키와 같다.
  - 대화에서는 ⌘\를 말했지만 이미 앱 메뉴 여닫기에 쓰이고 있어서 바꿨다. **[제안, 새로]**
  - 키는 `e.code === "KeyS"`로 본다. 한글 입력 중에는 `e.key`가 "ㄴ"이 되기 때문이다.
- 접으면 그리드가 한 칸이 되고, 메모는 지금 최대 폭(720px + 양옆 여백)을 지킨 채 가운데로 온다.
- 접힌 상태는 기기에 기억한다(`memo.listOpen`, 기본은 펼침).
- 접혀 있을 때 ⌘F를 누르면 목록을 펴고 검색칸으로 간다.
- 메모가 하나도 없으면 접힘 설정과 상관없이 목록(빈 안내)을 보인다.
- 900px 미만에서는 버튼이 없고, 저장된 값도 쓰지 않는다.
- 버튼에는 `aria-expanded`, `aria-controls`, `aria-keyshortcuts`를 단다.

### 5.7 글씨 크기 **[결정: 메모 화면 전체 / 제안: 세부]**

- 머리 막대의 "가" 버튼으로 단계를 고른다. 팝오버로 할지 Sheet로 할지는 **[빌더 재량]**이다.
- 단계는 배율 다섯 가지다. **0.875 · 1(기본) · 1.125 · 1.25 · 1.375** **[제안, 새로]**
  - 기준 크기는 넓은 화면 16px, 휴대폰 16.5px이다. 넓은 화면은 14~22px이 된다.
  - **휴대폰 폭(900px 미만)이나 터치 기기(`(pointer: coarse)`)에서는 1보다 작은 배율을 고를 수 없게 하고**, 저장된 값이 1보다 작으면 1로 쓴다. 아이폰 확대를 막기 위해서다. 가로로 돌린 큰 아이폰과 아이패드는 넓은 화면 배치가 되므로 터치 기기 조건이 함께 필요하다. **[제안, 새로]**
- 바뀌는 것은 **편집기 안의 글자뿐이다.** 본문, 첫 줄 이름, 제목, 구분선 위아래 간격, 들여쓰기 안내선이 여기에 들어간다. 이 값들은 이미 em 단위이거나 em 단위로 맞춘다. 목록, 폴더 줄, 머리 막대, 고친 시각 줄, 일정 이름표는 그대로 둔다. 대화에서 "본문과 제목, `#` 제목, 구분선 간격이 같은 비율로"라고 보여 드리고 동의를 받았다. 사용자가 말한 "메모 화면 전체"는 "글의 일부만"과 대비해 고른 답이다. **[결정: 전체 / 제안: 편집기 범위]**
- 기기에 기억한다(`memo.fontScale`).

### 5.8 제목 `#` `##` `###` **[제안]**

- **문법:** 들여쓰기 없이 줄 맨 앞에 `#`이 1~3개 있고, 띄어쓰기가 하나 이상 따라온다. `####`부터는 보통 글이다. `# `만 치고 글이 아직 없어도 제목 줄로 본다.
- **모양:** 모두 굵게(700) 보여 준다. 크기 순서는 첫 줄 이름(지금 1.6em) > `#` > `##` > `###` > 본문을 지킨다. 값은 대략 1.4 / 1.2 / 1.08em이고, 위쪽에 여백을 조금 준다. 정확한 값은 **[빌더 재량]**이다.
- **기호 보이기:** 커서나 선택이 걸친 줄에서는 `# `를 연필색(`--pencil`)으로 보여 주고, 다른 줄에서는 숨긴다. 숨길 때는 `Decoration.replace`를 쓰되, 원자(atomic) 범위로 만들지 않는다. 커서가 들어가면 기호가 다시 보여야 하기 때문이다.
- **첫 줄(이름 줄)의 `#`:** 크기는 이름 크기 그대로 두고, 기호는 위와 같은 규칙으로 숨긴다. 목록 이름에서는 기호를 뺀다. 일정 메모(`titled` 아님)의 첫 줄은 보통 제목 규칙을 따른다.
- **Enter:** 제목 줄 끝에서 Enter를 치면 다음 줄은 보통 글로 시작한다. 제목 줄 중간에서 치면 뒷부분이 보통 글이 된다. `#`은 글머리가 아니라서 지금 `continueList`도 이어 쓰지 않는다. 테스트로 확인한다.
- 제목 안에서도 굵게(`**`)를 쓸 수 있다.
- **아이폰 도구 막대 "제목" 버튼:** 커서가 있는 줄을 보통 → `#` → `##` → `###` → 보통 순서로 바꾼다. 들여쓰기나 글머리가 있는 줄은 그것을 떼고 제목으로 만든다. **[제안, 새로]**

### 5.9 구분선 `---` **[제안]**

- **문법:** 들여쓰기 없이 `-`만 세 개 이상 있는 줄이다. 뒤에 공백이 있어도 된다. `- `(`-` 뒤에 띄어쓰기)는 지금처럼 글머리표다.
- **모양:** 커서가 없는 줄은 가로선(1px, `--rule`, 줄 높이의 가운데)으로 그린다. 커서가 그 줄에 오면 `---` 글자를 연필색으로 보여 준다. 화살표 키로 그 줄에 들어갈 수 있다.
- 목록의 이름과 미리보기에서는 뺀다. 첫 줄이 `---`이면 그다음에 글이 있는 줄이 메모 이름이 된다.

### 5.10 이름과 미리보기 (`format.ts`)

- `plainLine`은 줄 앞의 `#{1,3}\s+`를 떼고, `^-{3,}\s*$`인 줄은 빈 줄로 만든다. 빈 줄은 이미 걸러진다.
- 검색은 지금처럼 원문으로 찾는다.

### 5.11 메모 끝 빈 공간 **[제안]**

- `.doc`의 아래 여백을 화면 높이의 절반으로 늘린다. 키보드 도구 막대가 있을 때도 같다. 값은 대략 `max(50dvh, 160px)`이다.
- 빈 공간(편집기 아래)을 누르면 커서가 메모 맨 끝으로 간다(`BlockEditorHandle.focus("end")`). 지금은 그곳을 눌러도 아무 일이 없다.

### 5.12 문서 고치기

- 상위 설계에 §11 개정 항목을 더한다. 요약 몇 줄과 이 문서로 가는 링크를 쓰고, §5.3 "이 밖의 서식은 없다"와 §9.1 "폴더는 이번에 넣지 않는다"를 고쳤다고 적는다.

### 5.13 테스트

지금의 vitest 구성(`store.test.ts`, `editor/editor.test.ts`, `server/api.test.ts`, `MemoPage.test.tsx`, `format.test.ts`)을 따른다. 꼭 확인할 것은 다음과 같다.

- **데이터와 API**
  - 폴더를 지워도 메모가 모두 남고, 폴더 밖으로 나온다. 색을 고르지 않았던 메모는 폴더 색을 그대로 지닌다.
  - 메모를 옮겨도(PATCH) `version`과 `updated_at`이 그대로이고, 그 뒤 옛 `baseVersion`으로 본문을 저장해도 409가 나지 않는다.
  - 지워진 `folderId`로 메모를 만들면 폴더 밖에 저장된다.
- **기기 안 상태**
  - 충돌 사본과 되살린 메모가 원래 폴더를 물려받는다.
  - 기기에 보관해 둔 새 메모가 폴더와 함께 서버에 간다. 예전 형식의 보관본도 읽힌다.
- **편집기**
  - 제목과 구분선이 그려지고, 커서가 있는 줄에서 기호가 보이며, 제목 줄에서 Enter를 치면 다음 줄이 보통 글로 시작한다.
- **이름과 미리보기:** `plainLine`이 `#`과 `---`를 정리한다.
- **보기 설정**
  - 휴대폰 폭이나 터치 기기에서 글씨 배율이 1 아래로 내려가지 않는다.
  - 목록 접힘이 기억되고, 접힌 상태에서 ⌘F를 누르면 목록이 펴진다.
- **검색:** 맞는 메모가 든 폴더만 펼쳐진다.
- `npm run typecheck`, `npm run lint`, `npm test`가 모두 통과한다.

## 6. 빌더에게 맡기는 것

- 정확한 크기·간격·아이콘 모양. 지금의 토큰(`src/ui/tokens.css`)과 테마 규칙(상위 설계 §10)을 따른다.
- 팝오버로 할지 Sheet로 할지, 넓은 화면에서 새 폴더 이름을 받는 방식.
- 폴더 목록을 메모 목록 응답에 함께 넣을지 따로 받을지.
- 폴더 줄에 메모 개수를 보여 줄지.
- 닫힌 폴더 안의 메모가 열려 있을 때의 표시.
- 휴대폰 머리 막대가 좁을 때 "저장했어요"를 어떻게 다룰지.
- `hueFor(id ?? key)`로 바꿀지.

## 7. 성공 기준

- 맥에서 만든 폴더, 옮긴 메모, 바꾼 색이 아이폰에서도 같게 보인다.
- 폴더를 지워도 메모가 하나도 사라지지 않는다.
- 한 기기에서 메모를 옮기는 동안 다른 기기에서 같은 메모에 쓴 글이 충돌 사본 없이 저장된다.
- `# `나 `---`를 치면 바로 제목과 선으로 보이고, 목록의 이름과 미리보기에는 기호가 보이지 않는다.
- 글씨 크기를 바꾼 뒤에도 아이폰과 아이패드에서 입력할 때 화면이 확대되지 않는다.
- 넓은 화면에서 ◧나 ⌥⌘S로 목록이 접히고, 새로고침한 뒤에도 접힌 채로 있다.
- 어떤 메모든 마지막 줄을 화면 가운데까지 올릴 수 있다.
